# Release plan

## Product target

Ship one experimental Cloudflare database path:

- Better Auth owns identity, sessions, and organizations.
- A Drizzle schema defines organization placement and policy.
- Registered mutations and bounded selects execute on SQLite Durable Objects.
- React queries stay live through the same authenticated query plan.
- Files use opaque row values backed by R2.
- Vectors use opaque row values backed by Vectorize, with SQLite as authority.
- Wrangler and Miniflare are the deployment and local-development runtimes.
- `wrangler.toml` is generated by default, with JSONC accepted for existing projects.

Do not add another tenancy mode, transport, query compiler, or public operator system before this release path passes as one packed candidate.

## Product and package contract

- [x] Keep the public package to `@chardb/core`, `@chardb/core/server`, `@chardb/core/react`, `@chardb/core/files`, and `@chardb/core/vite`.
- [x] Use Better Auth's native session and organization hooks in the generated React path.
- [x] Support organization-wide `forOrg()` tables and user-owned `forOrgUser()` rows inside an organization, with distinct organization-role, user-role, and `self` namespaces.
- [x] Compile registered queries and direct selects to one versioned plan and one Cdb executor.
- [x] Keep mutation input bounded, transactional, epoch-fenced, and replay-deduplicated.
- [x] Generate TOML-first Wrangler configuration and accept JSONC in doctor and preparation commands.
- [x] Keep unfinished presence, streams, distributed transactions, backup, restore, and PITR out of the public package.
- [x] Keep `@chardb/core/vite` limited to stable refs and browser erasure. Runtime manifests come from the `api` namespaces passed to `chardb()`.
- [x] Limit Vite discovery and browser erasure to query and mutation exports. Do not ship the unfinished dashboard virtual module or partial schema HMR hook.
- [x] Keep range movement behind `chardb experimental shards`, disable the old top-level command without an alias, and omit it from primary help and generated onboarding.
- [x] Generate the immutable initial migration from conventional `src/auth.ts` and `src/schema.ts` in two fresh Bun processes, reject nondeterminism, and emit static source that does not import either mutable module.
- [x] Append conservative additive migrations at any sequential version from a verified digest-chained JSON and TypeScript history without importing, editing, or regenerating prior versions.

## Final candidate

The final preview candidate must be packed once and reused unchanged.

- [x] Record the tarball byte count and SHA-256 digest.
- [x] Run `bun run test:correctness`.
- [x] Run the generated-project, package, chat, packed public-vector browser, file, combined movement, and deployed vector gates against that tarball.
- [ ] Run `bun run release:admit` with exactly `preview`, `cloudflare-files`, `cloudflare-file-reshard`, `cloudflare-vectors`, and `os-ci` evidence. The OS bundle must bind Ubuntu x64, macOS arm64, and Windows x64 reports from one GitHub Actions run to the same tarball.
- [x] Verify all report schemas and checksum manifests.
- [x] Scan public evidence for secrets.
- [x] Verify every disposable Worker, R2 bucket, and Vectorize index named by a proof ledger is absent after cleanup.
- [ ] Publish one status summary that links the admitted reports and lists unsupported behavior.

The production warning is a standing release invariant. Preview does not mean backup, restore, failover, regional resilience, or an SLA.

## Stop conditions

Stop a release proof and keep the gate open if any of these occur:

- a write-bearing operation would need blind replay after an ambiguous response;
- a migration serves application traffic before the new epoch is fully active;
- a report loses the exact candidate, runtime, workload, or cleanup identity;
- local and deployed comparison inputs differ;
- a disposable resource cannot be proven absent;
- vector deletion reaches `failed_unproven`, which requires operator intervention and does not prove external deletion;
- documentation claims more than the admitted report proves.

[STATUS.md](STATUS.md) reports the current result. [NEXT_SCOPE.md](NEXT_SCOPE.md) holds work that is not required for the preview candidate.
