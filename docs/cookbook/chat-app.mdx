This recipe uses the app from [Quickstart](/quickstart). Do not rebuild it by hand. The initializer already wires the server, browser, Miniflare test, migration journal, and deploy scripts.

## Establish the Better Auth session

```tsx
const authClient = createAuthClient({
  baseURL: window.location.origin,
  plugins: [anonymousClient(), organizationClient(), jwtClient()],
});

<ChardbProvider endpoint={endpoint()} auth={authClient}>
  <Workspace />
</ChardbProvider>
```

The generated browser signs in anonymously, creates an organization through Better Auth, and calls `organization.setActive`. The provider fetches the signed JWT used by live queries and mutations. File routes use the same-origin session cookie.

## Read the active organization

```tsx
const { data = [], state } = useQuery(listMessages, {
  organizationId,
  limit: 50,
});
```

The routing value does not grant access. Gateway verifies current membership and the table policy before it registers the query.

## Upload, then write

```tsx
const uploaded = selectedFile
  ? await attachment.upload({
      organizationId,
      file: selectedFile,
      idempotencyKey: retryKey,
    })
  : null;

await mutate({
  id: uuidv7(),
  organizationId,
  body,
  attachment: uploaded?.fileId ?? null,
  clientCreatedAt: Date.now(),
});
```

The message insert and file upload are separate operations. Reuse the same upload idempotency key when retrying the selected file. The row stores only the opaque file ID.

Open the same organization in two tabs and post a message. Both subscriptions should receive the replacement snapshot. Switch one tab to another organization and confirm it cannot read or download the first organization's data.

The generated Vitest covers the server write and read. The browser path adds live delivery and the authenticated file lifecycle.
