---
title: "Quickstart"
description: "Generate, check, and run the app shipped by @chardb/core 0.1.0."
---

You need Bun 1.2.22 or newer. Local development uses Wrangler and Miniflare, so a Cloudflare login is not required yet.

`chardb init` writes into the current directory. Create an empty one first:

```bash
mkdir my-chardb-app
cd my-chardb-app
bunx @chardb/core@0.1.0 init my-chardb-app
bun install
bun run typecheck
bun run test
bun run build
```

The CLI refuses a directory containing anything except `.git` and `.DS_Store`. It checks the whole write set before creating a file.

Now start both local servers:

```bash
bun run dev
```

The script starts Wrangler on `127.0.0.1:8787`, reads the packaged schema version from `/health`, applies that migration, and then starts Vite on `127.0.0.1:5173`. It prints the browser URL only after both are ready.

Open the printed URL. The generated app signs in anonymously, then lets you:

1. Create an organization.
2. Post a message and watch the live query replace its result.
3. Attach a JPEG or PNG through the local R2 binding.
4. Stop and restart `bun run dev`, then reload the persisted message.

The generated test covers the same server path inside Cloudflare's Vitest integration. It migrates a fresh database, checks the Durable Object and R2 bindings, creates a Better Auth organization, then writes and reads an organization message.

Next, read [Tenancy and auth](/build/tenancy-and-auth) before changing the schema. The generated migration is immutable once deployed.
